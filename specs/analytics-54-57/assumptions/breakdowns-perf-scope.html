PR #104 · 2026-10-25
Review fix · Breakdowns page speed

Scope limited to overrides and rate hoisting

ASSUMPTION

Only the pricing.json reads were fixed.

The review finding said the Breakdowns page got 5-10x slower because the new sections price every request in Python and re-read pricing.json each time. The fix hoists the overrides so the file is read once, and caches the per-model rate.

Context

The finding also suggested summing in SQL, and mentioned a compacted() lookup for each candidate miss.

Decision

Only hoisted the overrides and cached the per-model rate.

Alternatives

Batch the compacted() lookups, or move the sums into SQL.

Impact

Removes the repeated pricing.json reads, the main cost. The remaining speedup was not measured.
